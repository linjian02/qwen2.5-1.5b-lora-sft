# Qwen2.5-1.5B 话术微调实验包（RTX 3070 / 8G 显存 / Windows）

> **Windows 一键流程见 [`0_新手必读.md`](0_新手必读.md)，那是唯一的操作入口。**
> 这份 README 只做目录说明和原理解释。

---

## 这个包是干什么的

用 300 条业务话术数据，在 1.5B 的开源模型上做一次 LoRA 微调，然后用评测数据回答一个问题：

> **「微调之后，模型的格式合规率、数字幻觉率、延迟，到底比原来好多少？」**

这四个指标构成「Qwen2.5 指令微调与评测」这套工作的全部结论依据。

## 为什么是 1.5B 而不是 7B

| 模型 | 加载方式 | 训练占用 | 3070 8G |
|---|---|---|---|
| Qwen2.5-7B | 4bit | 约 9G | ❌ 爆显存 |
| Qwen2.5-3B | 4bit | 约 5G | ✅ 需额外装量化库 |
| Qwen2.5-1.5B | 半精度不量化 | 约 4.5G | ✅ 主力 |

Windows 会占用约 1G 显存给桌面显示，8G 卡实际只剩 6.5~7G 可用。1.5B 用半精度直接训，**顺带跳过了 `bitsandbytes` 这个最容易在 Windows 上装失败的依赖**。

而且在小数据（300 条）上做格式对齐任务，1.5B 和 7B 的差距远小于你想象；7B 反而更容易过拟合。

## 核心概念速查

**LoRA**：原模型一个字不动，只在旁边挂一个很小的「补丁」，训练时只更新补丁。1.5B 上补丁约 1,846 万参数，占 1.2%。

**r 和 alpha**：r 是补丁的厚度（秩），alpha 是音量（缩放）。alpha/r=2 是常见起点。面试问「r 为什么取 16」，答案应该是「我试了 8/16/32」，所以要跑三组。

**QLoRA**：把原模型压成 4bit 再训 LoRA。7B 必用，1.5B 不需要。

**为什么先切考卷再训练**：切出来的 100 条如果留在训练集里，模型就提前看过答案，评测分数虚高。这是新手最常犯的错。

## 四个指标分别在说什么

| 指标 | 回答的问题 | 理想方向 |
|---|---|---|
| 格式合规率 | 四段（开场/核心权益/办理引导/限制说明）齐不齐 | 越高越好 |
| 关键数字保留率 | 素材里该出现的资费、时限说了没 | 越高越好 |
| 数字幻觉率 | 有没有编出素材里没有的数字 | **越低越好** |
| P99 延迟 | 最慢的 1% 请求多久 | 越低越好 |

## 指标怎么引用

所有百分比一律以 `out/score_report.md` 的实测值为准。

**别估、别凑**。任何引用这个项目的场合都会被追问「怎么算的」，口径就在 `scripts/score.py` 里，可以逐行打开核对。
