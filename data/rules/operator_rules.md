# 规则表 · 星联通信（虚构主体）

> **这份表是本项目全部业务事实的唯一来源。**
> 「星联通信」是为训练与演示虚构的运营商主体，与任何真实运营商无关。
> 表里的资费、档位、时限、违约金、短信指令**全部是设计值，不是任何公司的真实规则**。

---

## 一、为什么是虚构的，而不是真实业务值

很多人第一反应是「得把数字换成公司真实值才真实」。恰恰相反：

**1. 你拿不到，也不该拿。**
真实资费表、工单、话术属于公司资产。离职带走、写进个人 GitHub 仓库，是合规风险，
不是「项目真实度」加分项。面试官看到一份带真实资费的项目，第一反应往往是「这人会不会也把我的数据带走」。

**2. 这个项目要证明的能力，跟真实资费无关。**
招聘方看的是：你会不会构造 SFT 数据、会不会做格式约束、会不会量化评测、会不会调 LoRA 超参。
**「59 元档含 20GB」这个数字是真是假，不影响上述任何一项能力的判断。**

**3. 虚构规则集反而让评测更严格。**
规则由你自己定义，你就能做到「每条 output 的数字都能追溯到素材」——这正是 `scripts/check_rules.py` 在查的事。
真实数据往往脏、口径不一、字段缺失，反而做不出干净的溯源校验。

**4. 面试时这是加分项，不是减分项。**
正确说法见本文末尾「面试怎么讲」。核心一句：**规则集是我设计的，所以每个数字我都能解释它为什么是这个值。**

## 二、事实边界（模型的作答范围）

模型只允许在这个虚构世界的规则内作答。三条硬约束：

| 约束 | 含义 | 违反后果 |
|---|---|---|
| **素材优先** | output 里每个数字必须出现在 input 素材中 | 判为数字幻觉，`check_rules.py` C2 直接 FAIL |
| **不做算术** | 需要结论值（折合金额、剩余量、节省额）时，**素材必须直接给出该值**，模型只做语言组织 | 模型自算会算错，且错误不可控 |
| **不补常识** | 素材没写的办理渠道、材料、时限，一律不许凭经验补 | 编造业务规则，是客服场景最严重的事故 |

第二条是这套数据最容易被忽略、也最值钱的设计。举例：

- ❌ 素材给「8,650 分、100 分抵 1 元」，让模型自己算 → 模型说「86 块多」（对）或「865 块」（错），全凭运气
- ✅ 素材直接给「8,650 分折合 86.5 元」→ 模型只负责把它说得像人话

**这就是 RAG 里「检索片段必须自包含答案」的原则。** 计算放在检索/工具层，模型只负责表达。

## 四、怎么用这张表扩到 301 条（已实施）

这是扩量的唯一依据。**新样本的事实字段必须全部来自本表**，不许现编。

实际做法是**代码生成**，不是手写：`scripts/gen_expand.py` + `scripts/scen_pack_{a,b,c}.py`。
每个场景在场景包里写一份 `facts` 字段表，再写 1 条标准答案和 3 条难例，**素材与答案由同一份字段渲染**，所以数字溯源在生成阶段就成立。

产出结构（231 条）：

| 类型 | 每场景 | 合计 | 说明 |
|---|---|---|---|
| 标准 | 1 | 33 | 完整素材 + 四段答案 |
| 人格改写 | 3 | 99 | 长者 / 着急 / 怀疑，只换问法与开场口吻 |
| 难例 | 3 | 99 | 每条删一个字段，答案必须明说「资料里没有」 |

加上原有手写 71 条（seed33 / sample_sft / hard_cases），去重后入库 **301 条，其中难例 120 条（40%）**。

三种扩量思路仍然有效，比例已经按下面调整过：

**1. 同场景换用户（占 43%，即人格改写）**
同一个 R 编号，换用户画像与诉求表达。事实字段完全不变，只变开场语境与语气。这类样本最贴近真实工单分布。

**2. 缺信息难例（占 43%，本项目最关键的一类）**
不是「换用户」，而是**故意让素材不完整**，标准答案是承认缺失并给下一步。例：
- 用户问欠了多少钱 → 素材没有金额 → 「资料里没有这笔金额，以账单页为准」
- 用户问多久复机 → 素材没有时限 → 「没给时限，我不敢说十分钟还是半小时」

没有这类样本，模型会拿预训练常识去填空，幻觉率压不下来。占比不能低于 4 成。

**3. 规则反推（可继续补）**
从用户可能的误解出发，用规则表纠正。例：
- 「我停机了是不是号就没了」→ R01 的 90 天红线
- 「合约到期是不是自动涨价」→ R21 的到期未续规则

## 五、加一条新规则时怎么做

1. 在本表新增 `R34` 段落，字段写全
2. 在 `seed33.jsonl` 追加一条对应样本，input 素材**逐字段**照抄本表
3. 跑 `python scripts/check_rules.py`，必须 PASS
4. 若 output 需要结论值（折合金额、剩余量、总节省），**先把它写进 input 素材**，再让 output 引用

第 4 步是这套流程和普通「让模型写答案」最大的区别，也是面试最能讲的一点。

## 六、面试怎么讲这套数据

被问到「你们的数据哪来的」时，标准答案：

> 这是我自己做的练手项目，用的是一套我设计的虚构规则集，不是公司真实数据。
> 真实资费、工单属于公司资产，我不带出来。
> 规则集共 33 个场景，每个场景的资费、时限、违约金都是我定的，所以每个数字我都能解释为什么是这个值。
> 这样做的好处是能做严格的溯源校验：我写了个脚本，检查每条样本 output 里的每个数字能不能在 input 素材里找到出处，50 条里查出 12 处模型自作主张的算术，全改成素材直接给结论。
> 我觉得这个比拿真实数据有意义——真实数据没人能验证，我这套能验证。

如果对方追问「那你没做过真实业务数据？」——不要含糊，直说：

> 真实工单我处理过，但那是公司数据，不能带走也不能写进项目。
> 这个项目要验证的是数据构造和评测方法，这两件事跟数据是不是真实资费无关。

**这套说法比任何编造都强。** 因为它同时展示了三件事：知道合规边界、有方法论、对自己的数据有掌控力。
